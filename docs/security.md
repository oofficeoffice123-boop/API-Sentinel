# Security notes

- Registration hashes passwords with ASP.NET Core `PasswordHasher<T>`. Fifteen-minute JWT validation checks issuer, audience, signature, expiration, and a database token version. Thirty-day refresh tokens are random, stored only as SHA-256 hashes, rotated on use, and sent to browsers in an HttpOnly, SameSite Strict cookie. A SQL row version blocks concurrent refresh reuse. Logout, password change, and email change invalidate all previously issued tokens for that user. Protected endpoints scope data reads and writes to the signed-in user.
- Saved Bearer, Basic, and API key credentials are protected at rest with ASP.NET Core Data Protection and omitted from API responses. Request headers and query parameters with credential-like names (including cookies, auth tokens, sessions, and signatures) are encrypted by the backend even if a client fails to mark them secret. Persist and protect the Data Protection key ring in production; losing it makes saved credentials undecryptable.
- Persisted execution evidence omits response headers classified as credentials, including `Set-Cookie`, `Cookie`, `Authorization`, auth tokens, sessions, signatures, and API keys. Run assertion snapshots and retained header values are bounded before storage.
- The Groq key is read only by the backend. AI prompts and response bodies are redacted for common credential field names, bearer values, provider keys, and email addresses; failure analysis sends only a bounded response excerpt and a sanitized target host. AI summaries send status and timing metadata only. AI content is validated and never executed. Configure Groq only when the feature is wanted.
- Outbound URLs are restricted to HTTP(S); loopback, private, link-local, metadata, documentation, benchmarking, translation, and local IPv6 ranges are blocked. The connector pins the validated DNS result for the connection, redirects are disabled, proxy use is disabled, and requests have timeout/response caps plus concurrency and per-user rate limits.
- Authorization headers and Host are not accepted as user supplied forwarding headers. Errors returned to users do not include exception details. A target HTTP 4xx/5xx is recorded as a response, not treated as an API Sentinel exception.
